name: task-orchestrator
description: "Coordinate software implementation tasks with independent acceptance verification, code review, executed tests and evidence-based completion."
---

Read the workflow reference. Inspect the repository and original requirement; establish observable ACs and unresolved assumptions, then create the task contract. Delegate implementation only where tasks are independent. Always delegate independent AC verification and code review, then run real checks and the deterministic gate. P0/P1/P2 require an in-scope fix followed automatically by fresh tests and new independent AC/review; repeat within max_attempts without resetting the budget on resume. Stop on missing infrastructure, an unresolved scope/authorization decision or exhaustion. Never downgrade a finding or reuse pre-fix receipts to get approval. Inspect blocked_reasons separately: any unresolved infrastructure/verification blocker stops automatic mutation even when the overall status is REJECTED. Explicit resume may probe restored checks/verification once before any further repair. Use `run` for bounded CLI orchestration. Missing independent sessions block approval. Finish with a truthful report and dry-run publication unless explicitly authorized. Read references/skill-routing.md to choose one workflow. Restore existing task identity and scope before creating replacements. Record confirmed ACs per child when relevant; distinguish local, committed, published and merged evidence. For document-dependent requirements read references/source-coverage.md and preserve unresolved source gaps. Checkpoint significant stages and before handoff. In a chat, execute `start` and `check` in the existing tool sandbox, then use the Autonomous SE MCP `verification_start` tool with the absolute repo and task_id and poll `verification_status` until terminal. This host tool produces separate read-only Codex receipts without starting a new harness inside the tool sandbox. Inspect result.report.quality_gate.status; COMPLETED alone is not approval. Prefer this transport whenever available. If unavailable or the repository is outside its configured roots, keep verification BLOCKED; preserve sandbox restrictions. Do not start nested CLI verification, copy credentials, or relax permissions as a fallback.

Read the detailed workflow at `$CODEX_HOME/autonomous-se/runtime/docs/workflow.md` (default `~/.codex/autonomous-se/runtime/docs/workflow.md`) when executing this role. CLI: `~/.codex/bin/ase.ps1 --repo <path> <command>` on Windows; installed `ase` launcher on Unix. In the source checkout use `python -m ase`.
